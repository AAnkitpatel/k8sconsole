Cluster Map & Relationships

Understand a namespace in one glance

Traffic flows left to right, from Ingress to Service to workloads to pods to the config and storage they depend on, and every box is coloured by health. Click anything to open it. Every object also gets its own relationship graph.

  • Ownership, selectors, routes, mounts, volumes, identities and network policies
  • A node map shows every pod placed on its node
  • Live: updates as your cluster changes
Amazon ECS

Your ECS services, next to your Kubernetes clusters

Switch the sidebar to Amazon ECS and connect with an AWS profile or your IAM role. Services, tasks and task definitions are live, with CloudWatch logs, CPU and memory charts, load balancer health and a service map from the load balancer down to every task.

  • Read-only by default: no change leaves the app until you switch it off
  • Stopped tasks with stop reasons and exit codes, so crashes are easy to explain
  • Scale, redeploy, roll back a revision, run one-off tasks and open ECS Exec shells, each with a confirmation
  • An ECS security scan for task definitions, services and open security groups
ECS services and tasks

Deployments, events, logs and health in one panel

Open a service to see its rollout, the tasks it runs, the latest service events, CloudWatch logs from every task, utilization over time and the health of each load balancer target.

  • Edit a task definition as JSON and register it as a new revision
  • An AWS shell in the integrated terminal, bound to your profile and region
GitOps

Flux and Argo CD, next to the workloads they deploy

Every Argo CD Application and Flux Kustomization, HelmRelease and source in one list, with sync and health state, source, revision and the error that is holding it up. Reconcile, suspend, refresh or sync from the same screen.

  • No GitOps agent or CLI needed: K8sConsole reads and patches the same resources the flux and argocd CLIs do
  • Every action asks for confirmation
Cost & security

Know what it costs, and what's vulnerable

Estimated monthly cost by namespace, workload and ECS service, with idle spend and rightsizing suggestions from live usage. Image vulnerability scanning covers what is actually running, from Trivy Operator reports or a local Trivy scan.

  • Rates you control (Fargate on-demand rates by default)
  • Smaller valid Fargate task sizes suggested from 24-hour utilization
  • Critical and high vulnerabilities per image, the fixed versions, and the workloads affected
Monitor

Live usage, without installing anything

CPU, memory, network and disk for the cluster, every node and every pod, with an hour of history. Usage bars show requests and limits, so you can see what's oversized and what's about to be throttled.

  • Reads the kubelet Summary API, or metrics-server when available
  • Sort pods by CPU, memory or restarts and drill into any of them
AI Assistant

Ask why. Get evidence, then a fix you control.

Ask a question in plain language. The assistant investigates with read-only tools (resources, events, logs, metrics, security findings) and explains what it found. When a change would help, it drafts the manifest for you to review, dry-run and apply.

  • It never changes your cluster on its own
  • Secret values are never sent; log access is your choice
  • Bring your own Claude API key, stored encrypted on your machine
Security Scan & Access

Find risky settings. Fix them in one click.

Checks pod security, RBAC and network exposure, gives a posture score, and explains every finding in plain language. Safe fixes come with the exact patch, a server-side dry run and an apply button.

  • Privileged containers, host access, root users, missing limits, wildcard roles, exposed services
  • "Who can delete pods here?", a permission matrix for any user, group or service account, and a visual role editor
Terminal

A real terminal that already knows your cluster

Open zsh or bash in a dock. Cluster shells are bound to the selected cluster and namespace without touching your kubeconfig. kubectl completion is loaded, and inline suggestions offer the commands you're most likely to need for the objects in front of you.

Event Timeline

Events laid out per object over time, with an activity strip and warnings highlighted, so the crash loop, the failed mount and the rollout line up on one screen.

Questions

Do I need to install anything in my cluster?

No. K8sConsole uses the Kubernetes API with the credentials in your kubeconfig. Monitoring reads the kubelet Summary API through the API server, or metrics-server if you have it.

Which clusters does it work with?

Any conformant Kubernetes cluster your kubeconfig can reach, self-hosted or managed. Cloud providers' sign-in plugins work the same way they do with kubectl: if kubectl can connect, K8sConsole can.

How does it connect to Amazon ECS?

With the AWS credentials you already use: a profile from ~/.aws (access keys, IAM Identity Center, or a profile that assumes a role), or the default credential chain, including the IAM role of the EC2 instance or container it runs on. You can also assume a role from the app. Keys stay on your machine and are never shown in the app.

Can it change my ECS services by accident?

AWS connections start read-only, and in that mode every create, update, stop or delete call is refused before it leaves the app. When you switch read-only off, each change still asks for confirmation, and deleting a service or scaling it to zero asks you to type its name. For extra safety, connect with a role that only has read permissions.

What does the AI Assistant send, and where?

Only when you use it: your question plus the cluster data it reads to answer (for example resource summaries, events and, if you allow it, log lines) go to the Claude API using your own API key. Secret values and credential-looking environment values are never sent. It can't change your cluster; you review and apply its proposals yourself.

Will it change anything without asking?

No. Every change shows a confirmation, edits support server-side dry runs, and destructive actions ask you to type the resource name.

macOS says it “could not verify K8sConsole is free of malware”. Is it safe?

macOS shows this for every app that isn't notarized by Apple; it doesn't mean anything was found. K8sConsole is open source and built by a public GitHub workflow. Every download has a checksum, a software bill of materials and signed build provenance you can verify (gh attestation verify <file> --repo AAnkitpatel/k8sconsole). To open it: click Done, go to System Settings → Privacy & Security, scroll down and click Open Anyway. Or run xattr -dr com.apple.quarantine /Applications/K8sConsole.app. Notarized builds are planned, and they won't show the warning.

Which platforms are supported?

Linux (a .deb for Ubuntu and Debian, x86-64), macOS (Apple Silicon and Intel) and Windows 10/11 (x64). Every installer is built and tested on its own operating system before each release.
